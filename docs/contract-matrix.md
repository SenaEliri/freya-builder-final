# Contract matrix: Freya Bank voice services mock

Sources: `sources/documents/2026-10-01-service-contract.md` (sections 3-6), `test-environment/test-customers.md`,
`test-environment/test-customers.json`, `cloudflare-mock/README.md` and `cloudflare-mock/example/worker.js`.

All seven services: `POST`, JSON in, JSON out, path `/voice/v1/<service>`. Request envelope
`{ "data": {...}, "call": {...} }`. Only `data` decides the answer; token, headers, `call` and `aiFlow` are not checked.

## Services

| Service | `data` fields (bold = must be present and non-empty) | Lookup key(s) | Success `data` | No fixture for the key |
|---|---|---|---|---|
| `cards.list` | **`customerNo`** (string or number), `aiFlow` | `customerNo` | `cards[]` (`cardNumber`, `cardNumberLast4`, `productName`, `status`, `isMainCard`), `validCardsCount`, `exitState` (`1_CARD` / `MULTI_CARD`) | 404 `FB_IVR_CHANNEL_102` |
| `cards.balance` | **`cardNumber`** | `cardNumber` | `cardNumber` (4+4 masking), `cardNumberLast4`, `productName`, `statementDate`, `lastPayDate`, `nextStatementDate`, `nextLastPayDate`, `debtTL`, `debtUSD`, `debtEUR`, `debtGBP` (may be absent), `statementPaymentStatus`, `totalDebtPaymentStatus`, `automaticPaymentFlag` | 404 `FB_IVR_CHANNEL_120` |
| `statement.week.get` | **`cardNumber`** | `cardNumber` | `cardNumber`, `cardNumberLast4`, `productName`, `statementWeek`, `statementDay`, four dates, `relationType`, `relatedCardNumber`, `relatedCardProductName` | 404 `FB_IVR_CHANNEL_121` |
| `statement.week.decide` | **`cardNumber`**, **`newStatementWeek`** (number or string), **`statementDay`** (value not checked) | `cardNumber`, then `newStatementWeek` | `statementDate`, `statementDueDate`, `statementDay`, `responseCode`, `responseMessage` | 400 `INVALID_ARGUMENTS_ERROR` |
| `statement.week.change` | **`cardNumber`**, **`newStatementWeek`**, **`statementDay`** (value not checked) | `cardNumber`, then `newStatementWeek` | `responseCode`, `responseMessage`, `statementWeek` (string), `statementDay` (string), `exitState` | 400 `INVALID_ARGUMENTS_ERROR` |
| `contact.email.get` | **`customerNo`**, **`intAddressInfoType`** (value not checked) | `customerNo` | `communicationType`, `ibanCountryCode`, `ibanAreaCode`, `ibanPhoneNum`, `ibanEmail`, `ttsEmail`, `commGramType`, `exitState` | 400 `INVALID_ARGUMENTS_ERROR` |

Order of evaluation: body parse -> `data` is an object -> required fields non-empty (400) -> fixture lookup ->
fixture's own status and body, or the "no fixture" error above.

## Key normalisation

- `customerNo`, `newStatementWeek`: number or string, compared as trimmed strings (`3`, `"3"`, `3.0` are the same week).
- `cardNumber`: compared exactly (surrounding whitespace trimmed, nothing else). Only the `cards.list` form
  `540000******1234` matches. The `cards.balance` form `5400********1234` does not.
- The card's current week has no `decide` / `change` entry and answers 400.

## Response envelope

- Success: HTTP 200, `{ "data": {...}, "result": {...} }`, `result.returnCode` `"1"`.
- Error: `{ "result": {...} }` only, no `data`. `returnCode` = `code`, `messageText` = `message`, `guid` = `details.guid`.
- Fixture bodies are returned unchanged (deep-equal and same key order). `http` and `delaySeconds` never appear in a body.

## Errors generated by the mock (no fixture exists)

| HTTP | `code` | `type` | `rootCause` | `message` |
|---|---|---|---|---|
| 400 | `INVALID_ARGUMENTS_ERROR` | `ERROR` | `InvalidArgumentsException` | `<field> cannot be empty` (`card number cannot be empty`, `intAddressInfoType cannot be empty`, ...), `request body is not valid JSON`, `data cannot be empty`, `customer <no> not found`, `statement week <w> is not available for card <card>` |
| 404 | `FB_IVR_CHANNEL_102` | `WARNING` | `...NotFoundException` | `Müşteriye ait geçerli kart bilgisi bulunamadı.` |
| 404 | `FB_IVR_CHANNEL_120` | `WARNING` | `...NotFoundException` | `Kart bakiye servisi hatası: kart bulunamadı` |
| 404 | `FB_IVR_CHANNEL_121` | `WARNING` | `...NotFoundException` | `Hesap kesim servisi hatası: kart bulunamadı` |
| 404 | `FB_IVR_CHANNEL_107` | `WARNING` | `...NotFoundException` | `Pdf dokümanı bulunamadı` |

`guid` is a fresh 32-hex value per generated error; `errorOrigin` is `ivr-gateway-test:ivr-channel-v0` as in the fixtures.
The contract gives no message for `FB_IVR_CHANNEL_121` and calls the `_120` text "just my example; only the code matters",
so those two texts and the 400 texts for unknown records are the mock's own wording.

Outside the contract: `405 METHOD_NOT_ALLOWED` for a non-POST call to a service path and `404 NOT_FOUND` for an unknown
path, both in the same `result` envelope. `GET /health` and `OPTIONS` (CORS) exist as in the organizer's example.
